# Mushroom Grove R04 — wider forest scatter and 20% faster vision

Based on the verified R03 checkpoint 1d274663aff9b781b61c47dd3e54764df3ba16db. This iteration implements the five numbered user screenshots (82287, 82289, 82291, 82293, 82295; latest annotated copies inspected). The screen compass directions and the built estate's actual tree inventory were used to infer the perimeter. The screenshots contain no camera coordinates: the tree correspondence is a grounded spatial interpretation, not a precise image-to-world measurement.

The irregular footprint is 1,023.90 m², versus the original radius-13 core's 530.93 m² (1.93×). It reaches the south oak at (188.137,148.983), west oak (163.373,158.420), west pine (161.079,166.835), NW birch (162.589,175.673), and the north/east fence margins at Z178.5 / X198.5. Fence positions are grounded in ESTATE 200×180 and buildBoundary. The original radius remains 13 solely to preserve the successful clearing's tree reservation; the expansion uses its own polygon, not a larger tree-removal radius.

The R03 tree inventory was captured before editing in r04-tree-survey.json. Additional mushroom placement takes the real built vegPlan trees as obstacles; none of the existing tree/collider generation code is modified. Existing R03 hero/nursery transforms remain. An independent seed adds 24 large/mid-sized adults in uneven pockets across the polygon, with small companions. Shapes and palettes reuse the existing instanced families. Six added specimens are giants; medium forms use lighter geometry. The central walking/viewing pocket is reserved, and new giants stay outside the original 12 m inner band so their caps do not obscure the player camera. No extra lights or spores are added; the 64 existing spores are redistributed across the larger footprint. Existing paths and safe tree margins are excluded from the new scatter.

The expanded polygon also blends the local camera/audio atmosphere, with a soft signed-distance transition. The legacy core and approach field remain, as do floor/indoor isolation, easing and exact-zero restoration. Scene lights/fog/time, puzzles, progression and saves are unchanged.

MushroomVision's shader clock is multiplied by **1.2**. All screen-space time terms (wave, lens, hue, fog drift) therefore flow 20% faster without stronger displacement or faster physical pulses/audio. Reduced motion still fixes the shader clock to zero. A stationary-camera QA mode verifies clock=12 at input time 10 and clock=0 for reduced motion, and captures a correctly timed six-second flow comparison clip.

Implementation checks: typecheck, 301 unit tests, four performance-policy tests and production build pass. Existing bundle-size warning remains. The reviewed game code is pushed on `feature/mushroom-grove-r04-scatter` at `69e73b39b6678ea5a679b075fc5fdbb218738923`; [GitHub CI](https://github.com/Algolon/Feh-Lu-We/actions/runs/38780040266) passes. This is a new feature branch; R03 and public production remain untouched.

## Actual-game validation

The final built estate contains **302 mushrooms**: the original 220 plus 24 scattered adults (six giants / 18 medium specimens) and 58 young companions. The runtime survey verifies that all **49** surveyed trees retain their exact X/Z/species and that none of the added adults violate the trunk safety margin. Static tests also verify mixed scales and coverage of all four sides, the clear approach lane, the central viewing pocket and the original floor/isolation/easing contracts.

Final evidence is in [r04-final](r04-final). Earlier draft images are superseded: the final source reserves the central sightline so an added giant cap cannot fill the camera there. The final screenshots use the same built asset that is packaged for the private preview; local build label `4ddbbe5` is equivalent game source to the reviewed remote commit (the later change only added a QA capture-set filter).


## Final evidence and performance

Twenty desktop captures (ten low / ten high) cover the normal exterior, approach, halfway, core, return view and all five expanded-edge viewpoints. All have GL error 0 and no camera/collider overlap. Portrait evidence is 390×844. The actual collision-driven round trip reaches >.999999 intensity, restores exactly 0 and leaves inventory/clues/progression unchanged. Audio pause/resume/mute/exit and reduced-motion uniforms are included in lifecycle metrics. The normal direct render path is retained outside the field.

|---|---:|---:|---:|---:|
| Outside | 30 | 30 | 389,600 | 485,116 |

Across the ten desktop poses: low maximum 130 calls / 632,651 triangles; high maximum 136 calls / 756,562 triangles. Low and the landscape benchmark fit the active PB01 development ceiling (150-call guide / 750,000 submitted camera triangles). High exceeds that triangle reference by about 0.9% at the west view, so it is not claimed to meet a 750k ceiling. No additional instanced mesh batches, lights, particle count or postprocessing taps were introduced. The larger scene costs about 95–100k extra submitted triangles at the matched mobile viewpoints.

GPU queries on this host use **SwiftShader software rendering**: outside/core/return medians 3587.33 / 1312.45 / 1377.68 ms, with sampled RAF rates .27 / .65 / .70 fps. These are not handset framerates and are too host-dependent for a reliable relative speed claim against the earlier R03 run. Physical Android sustained FPS, GPU cost and thermals remain unmeasured.

The [stationary clip](r04-final/stationary-flow-r04.mp4) holds the player at (181,161), yaw .2, pitch .05. Only the postprocess time advances. Thirteen actual-game frames sample 0–6 seconds at 2 fps (6.5 s file, silent); it is a sampled visual demonstration, not a performance or smooth-framerate recording. Runtime diagnostics prove clock 12 at input time 10, and clock 0 with reduced motion.
